## 1. 技术选型（定稿）

| 项 | 选型 | 说明 |
|----|------|------|
| 运行时 | .NET 8（`net8.0-windows`） | 与 XRecorder 一致；本机仅装 SDK 10，实测可正常构建 net8 目标，用 `global.json` 固定 SDK |
| UI | WPF | 成熟稳定，XRecorder 同款 |
| 托盘 | Hardcodet.NotifyIcon.Wpf 2.0.1 | XRecorder 已使用，复用经验 |
| 存储 | SQLite（Microsoft.Data.Sqlite 10.0.14 → SQLite 3.53.3） | 单文件本地库 |
| 全文索引 | **SQLite FTS5 + `tokenize='trigram'`** | 中文 1 字起可搜；`LIKE '%kw%'` 在 trigram 表上可走索引 |
| ORM | Dapper 2.1.89（枚举走自定义 TypeHandler） | 轻量，MVP 查询以搜索为主足够 |
| 剪贴板监听 | Win32 `AddClipboardFormatListener` | 比轮询更省资源 |
| 来源识别 | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 维护前台窗口快照 | 解决「复制后立刻切窗」导致的白名单漏判 |
| 全局热键 | Win32 `RegisterHotKey` | 轻量，无额外依赖 |
| 单实例 | 命名 Mutex + 命名管道 | Mutex 只能判重，唤起已有窗口要靠管道传消息 |
| 日志 | 自建极简文件日志（2MB 滚动） | 排障用；日志失败静默不影响主流程 |

## 2. 架构总览

分层清晰、单向依赖，核心是「监听 → 处理 → 存储 → 查询 → 展示」流水线。

```
┌─────────────────────────────────────────────────┐
│              表现层 (WPF UI)                       │
│  主窗口(列表+预览+搜索)  托盘菜单  设置窗口          │
└──────────────┬──────────────────────────────────┘
               │ (数据绑定 / 事件)
┌──────────────▼──────────────────────────────────┐
│              应用服务层 (Application)              │
│  ClipService(采集编排)  SearchService  TagService   │
│  SettingsService  ExportService                   │
└──────────────┬──────────────────────────────────┘
               │
┌──────────────▼──────────────────────────────────┐
│              领域层 (Domain)                       │
│  Clip 实体  ClipType枚举  ClipSource 领域规则      │
└──────────────┬──────────────────────────────────┘
               │
┌──────────────▼──────────────────────────────────┐
│         基础设施层 (Infrastructure)                 │
│  ClipboardMonitor  HotKey  SqliteRepository        │
│  SensitiveDetector  SourceResolver  Logger         │
└─────────────────────────────────────────────────┘
```

**依赖方向**：表现层 → 服务层 → 领域层 ← 基础设施层（依赖倒置，接口在领域层定义）。

## 3. 核心流程

### 3.1 剪贴板采集流水线

```
用户复制
   │
   ▼
ClipboardMonitor (AddClipboardFormatListener 收到 WM_CLIPBOARDUPDATE)
   │
   ├─ 暂停中？ ──→ 直接忽略
   ├─ 来源应用在白名单排除？ ──→ 忽略
   ├─ 非文本格式？ ──→ 忽略（首期仅文本）
   │
   ▼
ClipService 构建 Clip 实体（去重：与上一条内容相同则更新时间戳）
   │
   ▼
SqliteRepository.Insert  → 触发容量策略（超 5000 条清理）
   │
   ▼
EventBus 通知 UI 刷新（若无窗口，静默）
```

> 注：敏感内容**一律全部保存**，不做拦截（已定稿，见需求文档第 7 节）。

### 3.2 检索流程

```
快捷键 / 托盘 → 唤起主窗口 → 焦点定位搜索框
输入关键词 → SearchService 子串匹配(SQLite LIKE / FTS) + 时间范围筛选
列表实时刷新 + 命中高亮 → ↑↓ 选择 → Enter 复制回剪贴板 → 窗口可自动隐藏
```

### 3.3 手动收藏模式

```
全局热键 Ctrl+Shift+C → 主动把当前剪贴板内容标记为「收藏」
（在全量记录模式之外，提供「仅手动收藏才入库」的开关）
```

## 4. 数据模型（SQLite）

```sql
CREATE TABLE clips (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    content      TEXT    NOT NULL,          -- 原文
    content_hash TEXT    NOT NULL,          -- 去重指纹：换行归一 + 去尾随空白后的 SHA256
    type         INTEGER NOT NULL DEFAULT 0,-- ClipType: 0文本 1链接 2代码 3邮箱 4数字
    source_app   TEXT,                      -- 来源进程名（小写、无 .exe）
    source_title TEXT,                      -- 来源窗口标题
    is_pinned    INTEGER NOT NULL DEFAULT 0,
    is_starred   INTEGER NOT NULL DEFAULT 0,
    created_at   INTEGER NOT NULL,          -- 首次收录（Unix 毫秒）
    updated_at   INTEGER NOT NULL,          -- 最后一次复制（去重命中时刷新，列表排序依据）
    copy_count   INTEGER NOT NULL DEFAULT 1,-- 被复制次数
    note         TEXT                       -- 用户备注（P1 预留）
);

-- 去重靠指纹唯一约束，而不是「跟上一行比」：A→B→A 不会再产生两条 A
CREATE UNIQUE INDEX ux_clips_hash ON clips(content_hash);
CREATE INDEX idx_clips_order ON clips(is_pinned DESC, updated_at DESC);
CREATE INDEX idx_clips_type ON clips(type);

CREATE TABLE tags (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE clip_tags (
    clip_id INTEGER NOT NULL REFERENCES clips(id) ON DELETE CASCADE,
    tag_id  INTEGER NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
    PRIMARY KEY (clip_id, tag_id)
);

-- 全文索引：external content 模式，正文只存一份在 clips
CREATE VIRTUAL TABLE clips_fts USING fts5(
    content, content='clips', content_rowid='id', tokenize='trigram'
);

-- 三条触发器保持索引与正文同步（含删除与正文更新）
CREATE TRIGGER clips_ai AFTER INSERT ON clips BEGIN
    INSERT INTO clips_fts(rowid, content) VALUES (new.id, new.content);
END;
CREATE TRIGGER clips_ad AFTER DELETE ON clips BEGIN
    INSERT INTO clips_fts(clips_fts, rowid, content) VALUES ('delete', old.id, old.content);
END;
CREATE TRIGGER clips_au AFTER UPDATE OF content ON clips BEGIN
    INSERT INTO clips_fts(clips_fts, rowid, content) VALUES ('delete', old.id, old.content);
    INSERT INTO clips_fts(rowid, content) VALUES (new.id, new.content);
END;
```

**ORM 选型说明**：
- 用 `Microsoft.Data.Sqlite` + Dapper，避免 EF Core 的重型启动。
- 注意两个坑，代码里都已处理：
  1. SQLite 的 INTEGER 读出来是 `long`，Dapper 默认的枚举转换按 `int` 拆箱会抛异常 → 给 `ClipType` 注册 `SqlMapper.TypeHandler`。
  2. Dapper 按属性名匹配列名，snake_case 列必须显式 `AS` 别名。

**搜索为什么统一走 `LIKE` 而不是 `MATCH`**（实测结论）：
- `MATCH` 要求查询串 ≥3 字符（trigram 的固有约束），而中文高频查询常常是 1~2 字（「密码」「链接」），实测 `MATCH '密码'` 直接返回 0 条；
- `LIKE '%密码%'` 在 trigram 表上结果全部正确，且 ≥3 字符时能走索引；
- `MATCH` 遇到 `"` 等字符需要手工转义，否则报 `unterminated string`；`LIKE` 用参数绑定天然免疫，只需转义 `%` `_` `\`。
- 因此：**查询统一 `WHERE clips_fts.content LIKE @pattern ESCAPE '\'`**，一次覆盖所有长度。

## 5. 关键技术点

### 5.1 剪贴板监听（省资源方案）

用 `AddClipboardFormatListener(hwnd)` 注册消息监听，收到 `WM_CLIPBOARDUPDATE` 再读取剪贴板，**避免 Timer 轮询**带来的空转 CPU。需要处理：

- 一个隐藏的 `HwndSource` 消息窗口承载监听。
- 读剪贴板失败（被其他程序占用）时**短暂重试 2~3 次**，不阻塞。
- 剪贴板在「同一内容重复复制」时去重（更新 `updated_at`，不新增行）。

### 5.2 敏感内容策略（已定稿：全部保存）

**决策：不管内容是否敏感，一律全部保存**，不做启发式检测、不拦截、不提示。

> 理由（用户确认）：用户对本地数据有完全掌控权（能暂停、能删、能白名单），无需软件替用户判断。
> 安全提示：由于可能采集到密码/密钥，**建议**在设置中保留「暂停采集」和「应用白名单」作为主动规避手段。

**实现约束**：
- 不做敏感检测，因此没有 `SensitiveDetector`，也没有对应配置项。
- 白名单默认预置常见密码管理器（`1password` / `keepass` / `keepassxc` / `bitwarden` / `lastpass`），用户可增删。

### 5.3 来源应用识别（已修正）

**不能**在剪贴板事件到达时才调 `GetForegroundWindow` 取来源。真实场景：在密码管理器里 `Ctrl+C` 后立刻 `Alt+Tab`，等 `WM_CLIPBOARDUPDATE` 被处理时前台已经是别的程序，白名单不命中，**密码会被静默收录**。

**实现方式**：`SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS)` 持续维护「最近前台窗口」快照（HWND + 进程名 + 标题），剪贴板事件到达时只读快照。

- 回调委托必须由字段持有，否则被 GC 回收会导致回调野指针。
- 只认进程名（不含 `.exe`，忽略大小写），**局限**：区分不了浏览器里打开的「网页版密码管理器」，这一点在设置界面已明示。
- 该机制同时提供事件发生时刻的时间戳，便于将来排查「来源不准」的反馈。

### 5.4 全局热键

`RegisterHotKey` 注册：

- **默认 `Ctrl+Alt+V`：唤起主窗口**
- **默认 `Alt+C`：手动收藏当前剪贴板**
- **首次启动弹设置窗口，由用户自己选定**（可改、可停用）

默认值刻意避开 `Ctrl+Shift+V` / `Ctrl+Shift+C`：前者是 VS Code / Chrome / Windows Terminal 的「粘贴为纯文本」，后者是终端「复制」。`RegisterHotKey` 是**系统级独占**，注册成功后这些程序在本地按同一组合键会直接收不到，属于破坏其他软件的行为。

注册失败（如 `ERROR_HOTKEY_ALREADY_REGISTERED` 1409）必须如实上报：启动时写状态栏并记日志，保存设置时弹窗提示换键。

## 7. 配置与数据路径

| 项 | 路径 |
|----|------|
| 数据库 | `%LOCALAPPDATA%\ClipNest\clipnest.db` |

```json
{
  "enableMonitor": true,
  "manualOnly": false,
  "maxItems": 5000,
  "maxContentChars": 200000,
  "hideOnLostFocus": true,
  "excludedApps": ["1password", "keepassxc"],
  "hotkeys": {
    "toggleWindow": "Ctrl+Alt+V",
    "manualCapture": "Alt+C"
  },
  "autoStart": false,
  "theme": "Light",
  "accentColor": "Teal"
```

> `theme` 取 `Light` / `Dark` / `System`（用字符串而非数字，方便手改）；`accentColor` 为
> `Teal` / `Indigo` / `Violet` / `Amber` / `Rose` / `Slate`，写错会自动回退到 `Teal`。

## 8. 非功能实现要点

| 目标 | 实现方式 |
|------|----------|
| 单实例 | 命名 Mutex 判重 + **命名管道**通知已有实例唤起窗口（Mutex 本身不能传消息） |
| 开机自启 | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，写 `"<exe>" --tray` |
| 内存 | WPF 单窗口 + 列表虚拟化（`VirtualizingStackPanel` + `Recycling`）+ 分页 500 条。**实测 Release 空载：私有内存 48MB / 工作集 128MB**，见下方说明 |
| 搜索 < 100ms | FTS5 trigram 索引 + `LIKE`；实测 5000 条下 1~3ms |
| 不丢数据 | SQLite WAL + `synchronous=NORMAL` + 写入事务 + 异常兜底日志 |

> **内存指标口径**：原目标「<100MB」未说明口径。实测 Release 版空载为 **私有内存 48MB、工作集 128MB**
> （工作集里包含 WPF/DirectX 的共享页）。建议把验收指标改成「私有内存 < 100MB」，工作集不作硬性要求。
> 若坚持按工作集考核，需要后续做启动优化（延迟创建主窗口、Release 裁剪、关闭硬件加速等）。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 剪贴板被其他程序占用导致读取失败 | 漏采 | 短重试 + 下次复制补偿 |
| 万条级数据列表卡顿 | 性能 | 虚拟化 + 分页加载 + FTS5 |
| 剪贴板内容变化极快（如连续复制） | 大量入库 | 去重合并 + 容量上限 |
| 采集到敏感内容 | 隐私风险 | 本地不联网 + 暂停/白名单主动规避 |
| WPF 高 DPI 显示 | 界面模糊 | 启用 PerMonitorV2 DPI 感知 |

## 12. 实施修正记录（2026-10-29，M3.1–M3.4 落地后回填）

本节记录**实际写代码时推翻或补充的设计**。凡与上文冲突，以本节为准。

### 12.1 已修正的设计缺陷

| # | 原设计 | 问题 | 现方案 |
|---|--------|------|--------|
| 1 | 敏感内容「默认不存 + 提示」 | 与需求文档第 7 节「已定稿」的另一结论直接对立 | 一律全存，无检测器；两份文档已统一 |
| 2 | 建 `idx_clips_search ON clips(content)` 用 LIKE | 实测执行计划是 `SCAN`，前导通配符用不到 B-tree 索引 | 删掉该索引，改 FTS5 trigram，`LIKE` 走索引 |
| 3 | 去重「与上一条相同则更新时间戳」 | A→B→A 会产生两条 A；且只刷 `updated_at` 却按 `created_at` 排序，顺序语义矛盾 | `content_hash` 唯一索引做全距去重；列表统一按 `is_pinned DESC, updated_at DESC` 排序 |
| 4 | 事件到达时 `GetForegroundWindow` 取来源 | 复制后立刻切窗 → 白名单漏判 → 密码入库 | `SetWinEventHook` 维护前台快照，见 §5.3 |
| 5 | 默认 `Ctrl+Shift+V` / `Ctrl+Shift+C` | 全局独占会抢掉 VS Code / Chrome / 终端的粘贴与复制 | 默认 `Ctrl+Alt+V` / `Alt+C`，且首启由用户选定 |
| 6 | 单实例「命名 Mutex 唤起已有窗口」 | Mutex 不能传消息，无法唤起 | Mutex 判重 + 命名管道发 `show` 命令 |
| 7 | 服务层命名空间 `Application` | 遮蔽 `System.Windows.Application` | 改名 `ClipNest.Services` |
| 8 | 容量清理未定细节 | 小上限时缓冲量大于上限会把库删空；置顶+收藏超上限时永远清不掉 | 缓冲取 `min(maxItems/2, max(20, maxItems/20))`；置顶/收藏永不自动删，允许超限 |
| 9 | 未处理「自己写剪贴板」的回声 | 点历史条目复制 → 又触发采集 → 复制次数虚增 / 刚删的又回来 | `ClipboardWriter` 记录自写指纹，1.5s 内的相同内容视为回声丢弃 |

### 12.2 新增的边界处理

- **空内容与纯空白**：不收录（密码管理器复制后自动清空剪贴板会触发一次空更新）。
- **超大内容**：超过 `MaxContentChars`（默认 20 万字符）截断并标注，避免一次粘贴几 MB 日志撑爆 trigram 索引。
- **剪贴板被独占**：读取失败后用 `DispatcherTimer` 延迟重试 3 次（120ms 间隔），不阻塞 UI 线程。
- **配置损坏**：`settings.json` 解析失败时备份为 `.corrupted` 并回退默认值，不让应用起不来。
- **窗口定位**：按鼠标所在显示器的工作区定位（`GetCursorPos` + `MonitorFromPoint`），水平居中、垂直 1/4 处。
- **虚拟化陷阱**：`ListBox` 不得放进外层 `ScrollViewer`，否则虚拟化失效（万条必卡）。

### 12.3 与文档不一致、需你确认的两处

1. **托盘气泡**：实现里只用于「主动收藏成功」和「注册/读写出错」两类明确反馈，
   **普通复制不弹任何提示**——遵循「安静运行」原则。若你希望每次收录都有感知，需要另加轻量的托盘图标闪动。

### 12.5 主题与设置界面（2026-10-29 追加）

**需求**：设置页改成顶部选项卡；支持 Windows 浅色/深色，默认浅色；可选主题色。

**实现要点**：

1. **画刷不能写在 XAML 里**。所有颜色由 `UI/Theming/ThemeService.cs` 在运行时算好后写进
   `Application.Resources`，XAML 一律用 `DynamicResource` 引用。
   如果图省事写成 `StaticResource`，切换主题时已经加载的控件不会重绘——这是本次改动最容易踩的坑。
2. **两条正交的维度**：明暗（浅色/深色/跟随系统）× 主题色（青绿/靛蓝/紫罗兰/琥珀/玫瑰/石墨）。
   暗色下主题色要提亮 28%，否则深色底上的小字对比度不够；`AccentSoft` 与 `SelectedBg`
   由主题色与背景色按比例混合得到，不另外维护六套色板。
3. **跟随系统**：读 `HKCU\...\Themes\Personalize\AppsUseLightTheme`，并监听隐藏窗口收到的
   `WM_SETTINGCHANGE`（lParam 为 `ImmersiveColorSet`）实时切换。
   只有「跟随系统」模式才响应系统变化，否则用户手选的模式会被系统悄悄改掉。
4. **主题变更立即预览，取消可还原**：设置窗口里改外观马上生效，点「取消」时重新应用已保存的配置。
5. **设置页改为 5 个顶部选项卡**：采集（含容量）、隐私、快捷键、外观、其他。
   校验失败会自动跳到出问题的那个选项卡，而不是把错误提示留在看不见的地方。

> 实测：本机 Windows 处于深色模式，`theme: "System"` 时应用正确解析为深色。

### 12.7 历史选择菜单（CLCL 式，2026-10-29 追加）

**需求**：按 `Alt+C`（可配置）弹出历史菜单，选中一条后**直接粘贴到当前光标所在的输入框**。

原先该快捷键的语义是「强制收藏当前剪贴板」，这次改成了「打开选择菜单」，同时保留原能力：

- 弹窗**之前**先按 `manual: true` 收一次当前剪贴板。这样「仅手动收藏模式」仍有采集入口，
  刚复制的内容也会排在列表第一条，可以直接回粘。

**粘贴链路**（顺序不能错）：

1. 按快捷键时立刻取 `GetForegroundWindow()`——弹窗一出现前台就变成我们自己了。
2. 弹窗用非模态 `Show()` + `Topmost`，出在鼠标右下方，贴边自动翻转。
3. 选中后**先 `Hide()` 让出前台**，再写剪贴板 → `SetForegroundWindow(目标)` → 等 90ms → `SendCtrlV()`。
4. 用 `SendInput` 合成真实按键，而不是给子窗口发 `WM_PASTE`：浏览器和 Electron 应用只认真键盘消息。
5. 目标窗口若属于本进程或已销毁，只复制不模拟按键，避免 Ctrl+V 打进 ClipNest 自己的搜索框。

**为什么不用模态 `ShowDialog()`**：模态会阻塞热键回调，而粘贴需要 `await` 一段延时等焦点切换；
非模态 + 失焦自动关闭更简单，也不会和主窗口的失焦隐藏逻辑打架。

**已知取舍**：位置按鼠标而不是按文本光标（拿光标矩形要走 `GetGUIThreadInfo`，对不同控件不通用）；
自动粘贴依赖模拟按键，个别以管理员权限运行的程序会拒绝接收普通权限进程的输入——这种情况内容已在
剪贴板里，手动 Ctrl+V 即可，日志会记一条。

**定位与单击（2026-10-29 补充）**：

- 菜单左上角**直接落在鼠标位置**（和右键菜单一致），只做屏幕内夹取；
  定位放在 `SourceInitialized` 而不是 `Loaded`，否则窗口会先出现在默认位置再跳一下。
  高度是内容撑出来的，`Loaded` 里再纠一次底部越界。
- **单击即粘贴**：原先只有双击/回车，现在单击任意一行就立即提交。
  事件用 `AddHandler(MouseUpEvent, h, handledEventsToo: true)` 注册在 ListBox 上——
  一是 `PreviewMouseLeftButtonUp` 是 Direct 事件、不沿树传递，二是即便 ListBoxItem
  把 MouseUp 标成已处理也仍要收到。
  点击滚动条或空白处时取不到 `ListBoxItem` 的 DataContext，自然忽略。

**粘贴完全没反应的根因（P/Invoke 结构体尺寸）**：

`INPUT` 在 C 里是 `{ DWORD type; union { MOUSEINPUT; KEYBDINPUT; HARDWAREINPUT; }; }`，
x64 下 **sizeof = 40**（type 4 + 对齐 4 + union 32）。最初按「type + KEYBDINPUT」顺序排，
得到 32 字节，`SendInput` 拿到的 `cbSize` 与系统期望不符，直接返回 **0** —— 一个按键都没发出去。

这类失败很隐蔽：`SendInput` 不抛异常，返回值被 `== inputs.Length` 一比较就成了「失败」，
但当时的代码只记了一行日志，表现就是「菜单消失了但什么都没粘贴上」。

修正方式：显式重叠两个分支，让 union 大小由 `MOUSEINPUT` 决定，`cbSize` 自然等于 `sizeof(INPUT)`：

```csharp
[StructLayout(LayoutKind.Sequential)]
private struct MOUSEINPUT { public int dx, dy; public uint mouseData, dwFlags, time; public IntPtr dwExtraInfo; }

[StructLayout(LayoutKind.Explicit)]
private struct INPUT
{
    [FieldOffset(0)] public uint type;
    [FieldOffset(8)] public MOUSEINPUT mi;   // 只为撑开 union，不实际使用
    [FieldOffset(8)] public KEYBDINPUT ki;
}
```

**验证手段**（这套脚手架值得留着复用的思路）：起一个独立的 WPF 小程序作为粘贴目标，
窗口里放一个 TextBox，每 300ms 把内容落盘到文件；主测试进程弹菜单、模拟点击，
再读那个文件断言内容。因为目标必须是**另一个进程**，同一进程会被「目标是自身则不粘贴」的
保护逻辑拦下。

### 12.8 详情页就地编辑剪贴板内容（2026-10-29 追加）

**需求**：主窗口详情页的正文可直接修改；第一排增加「保存 / 后退 / 前进」图标按钮。用户改完点保存，
即改写该片段的内容，且**之后的复制与就地粘贴都用保存后的新内容**。

**数据一致性链路**（顺序不能乱）：

1. `IClipRepository.UpdateContent(id, content)` 改写 `clips.content`，重新计算 `content_hash`、
   刷新 `updated_at`；`clips_au` 触发器自动同步 `clips_fts`，无需手动维护全文索引。
2. `ClipRow.UpdateContent(content)` 刷新内存模型。**复制 / 就地粘贴读的就是 `row.Content`**，
   模型更新后粘贴立即用新文本。
3. `ClipboardWriter.TrySetText(content)` 同步系统剪贴板。写入方记录指纹，1.5s 内的相同读取判为
   回声丢弃 —— 所以这次写回**不会**又被采集成一条新记录。
4. `IsDirty` 复位，状态栏提示已保存；保存按钮的 `CanExecute` 依赖 `IsDirty`，无改动时自动禁用。

**编辑态设计**：`MainViewModel` 增加 `EditContent`（工作副本，TwoWay 绑定到 `ContentBox`，
`UpdateSourceTrigger=PropertyChanged`）与 `IsDirty`。切换 `SelectedRow` 时把原文灌进 `EditContent`
并清空脏标记 —— 即**切换片段会丢弃未保存的修改**（不做草稿暂存，符合本地小工具的克制定位）。
「后退 / 前进」直接复用 WPF 原生命令 `ApplicationCommands.Undo / Redo`，`CommandTarget` 指向
`ContentBox`，用文本框自带的撤销栈，省去自己维护历史。

**两个必须处理的交互冲突**：

| 冲突 | 处理 |
|------|------|
| 窗口级 `PreviewKeyDown`（隧道事件）会抢走编辑框的按键 | 加 `ContentBox.IsKeyboardFocusWithin` 判断：编辑框内不把 `Delete` 当「删除条目」、不把 `/` 当「回到搜索框」，交还文本框正常编辑；`Ctrl+S` 在编辑框内特意映射为「保存」，框外仍是「收藏」 |
| 对 A 片段的撤销操作误伤 B 片段 | 订阅 `SelectedRow` 变化，切换后 `Dispatcher.BeginInvoke` 延迟 toggle `ContentBox.IsUndoEnabled` 清空撤销栈（延迟是为了等新内容绑定灌完） |

**验证**：Release 0 错 0 警、77 单测全绿；另起临时 WPF 脚手架按真实启动顺序加载资源字典并构造真实
`MainWindow`，实测：窗口可构造、`ContentBox` 可编辑且撤销启用、保存后 DB 内容与内存模型内容均为新值、
脏标记复位 —— 全部通过。
