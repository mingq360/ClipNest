# ClipNest 需求规格文档

> 本地优先的个人碎片信息收集工具
> 版本：v0.2
> 日期：2026-10-29
> 状态：**已定稿，MVP 进入开发**（技术方案见 `docs/方案设计文档.md`，实施修正见其第 12 节）

---

## 1. 产品定位

ClipNest（剪贴巢）是一个**本地优先**的个人碎片信息收集工具，核心解决一个问题：

> 复制过的文字、代码、链接等碎片信息，一闪而过就找不回来了。

它像一只「收巢的鸟」，默默把剪贴板里你复制过的片段收进本地仓库，让你随时能搜回来、翻出来、再复制走。

**一句话：** 你的剪贴板历史 + 可搜索的个人碎片仓库。

---

## 2. 核心原则（不可妥协）

1. **本地优先（Local-First）**：所有数据只存在本机，默认不上云、不联网、不登录。
2. **隐私第一**：剪贴板可能包含密码、密钥、聊天记录等敏感内容，必须让用户能完全掌控（能关、能删、能白名单）。
3. **安静运行（Quiet）**：常驻托盘，不打扰；只在需要时出现。
4. **即用即搜**：收集是顺手的，检索必须快到「肌肉记忆」级别。

---

## 3. 目标用户与场景

| 角色 | 典型场景 |
|------|----------|
| 开发者 | 复制了一段报错信息、一个 URL、一段 SQL、一个 token 想留档 |
| 写作者/研究者 | 复制了金句、数据、引用、资料片段 |
| 普通用户 | 复制了地址、账号、临时验证码想快速找回 |

**高频痛点场景：**
- 复制 A → 又复制 B → 想找回 A，却发现剪贴板已被覆盖。
- 三天前复制过一段东西，隐约记得几个字，但找不到出处。
- 不想开笔记软件、不想切窗口，只想「复制即收藏」。

## 4. 功能需求

### 4.1 核心功能（MVP，P0）

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | **剪贴板监听** | 后台监听系统剪贴板变化，自动捕获复制的文本片段 |
| F2 | **历史列表** | 按时间倒序展示已捕获的片段，支持滚动浏览 |
| F3 | **全文搜索** | 关键词/模糊搜索历史片段，命中即时高亮 |
| F4 | **一键复制** | 点击历史条目，立即重新复制回剪贴板 |
| F5 | **本地持久化** | SQLite 单文件存储，重启不丢失 |
| F6 | **托盘常驻** | 最小化到系统托盘，全局快捷键唤起主窗口 |

### 4.2 增强功能（P1，MVP 后可迭代）

| 编号 | 功能 | 说明 |
|------|------|------|
| F7 | **固定/置顶（Pin）** | 将常用片段置顶，不被滚动淹没 |
| F8 | **标签（Tag）** | 给片段打标签，按标签筛选 |
| F9 | **收藏（Star）** | 标记重要片段 |
| F10 | **删除/清空** | 单条删除、批量删除、一键清空 |
| F11 | **来源识别** | 记录来源应用（浏览器/编辑器/终端等），按来源筛选 |
| F12 | **类型图标** | 区分链接/代码/纯文本/邮箱/数字等，列表可视化 |

### 4.3 隐私与安全（P0，贯穿始终）

| 编号 | 功能 | 说明 |
|------|------|------|
| S1 | **暂停采集** | 一键暂停/恢复剪贴板监听（如输密码时） |
| S2 | **应用白名单** | 指定「不采集」某些应用（如密码管理器、网银） |
| S3 | ~~敏感检测~~ **已砍** | 2026-10-29 复议决策：一律全存，不做检测、不拦截、不提示（见 §7 #4） |
| S4 | ~~加密存储~~ **已排除** | MVP 不做。`Microsoft.Data.Sqlite` 不支持加密，要换 `SQLitePCLRaw.bundle_e_sqlcipher`，属选型级改动，留到 v2 评估 |
| S5 | **本地导出/导入** | 导出为 Markdown/JSON，并**支持导入回填**，用于备份与迁移（注意：方案初稿只写了导出，导入已补回） |

### 4.4 交互体验（贯穿）

| 编号 | 功能 | 说明 |
|------|------|------|
| U1 | **全局快捷键** | 自定义组合键快速唤起（默认如 `Ctrl+Shift+V`） |
| U2 | **即时预览** | 列表选中即显示完整内容预览，无需二次点击 |
| U3 | **键盘优先** | 全程可用键盘操作（↑↓ 选择、Enter 复制、/ 搜索） |
| U4 | **开机自启** | 可选，登录后自动后台运行 |

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 平台 | Windows（首期）；架构预留跨平台 |
| 技术栈 | .NET（C#），桌面 UI 待定（WPF / WinUI 3 / Avalonia） |
| 存储 | SQLite 单文件，路径默认 `%LOCALAPPDATA%/ClipNest/clipnest.db` |
| 性能 | 监听延迟 < 200ms；万条级历史搜索 < 100ms；内存占用 < 100MB |
| 隐私 | 不联网、不上传、不采集图片（首期仅文本） |
| 可靠性 | 异常不丢数据；剪贴板格式变化容错 |

---

## 6. 边界（MVP 明确不做的）

- ❌ 不做云同步 / 多设备同步（本地优先，首期明确排除）
- ❌ 不做图片 / 文件剪贴板内容（首期仅文本片段）
- ❌ 不做 OCR / 截图识别
- ❌ 不做协作 / 分享 / 发布
- ❌ 不做移动端

## 7. 开放问题定稿（2026-10-29 已决策）

| # | 问题 | 决策 | 理由 |
|---|------|------|------|
| 1 | 图片/富文本 | **首期仅纯文本**，富文本降级为纯文本，图片忽略 | 复杂度可控，隐私安全，后续可扩展 |
| 2 | 存储容量策略 | **默认上限 5000 条**，超过后按「先删最旧、保留置顶/收藏」自动清理；可配置 | 防无限膨胀，保留有价值内容 |
| 3 | 全量 vs 手动 | **默认全量记录，提供「手动收藏模式」切换**（全局快捷键 `Ctrl+Shift+C` 主动收藏） | 兼顾顺手与克制 |
| 4 | 敏感内容策略 | **一律全部保存**，不做敏感检测、不拦截、不提示；用户靠「暂停采集」与「应用白名单」主动规避 | 用户对本地数据有完全掌控权，软件不替用户判断（**2026-10-29 复议，推翻原「默认不存 + 提示」方案**） |
| 5 | UI 框架 | **WPF（net8.0-windows）**，与 XRecorder 完全一致，复用 Hardcodet.NotifyIcon.Wpf | 统一技术底座，降低维护成本 |
| 6 | 搜索能力 | **MVP 直接上 SQLite FTS5 + trigram 分词**，`LIKE` 子串匹配（中文 1 字起可搜）；拼音/正则列为 P1 | 原计划「MVP 用 LIKE 全表扫描、P1 再换 FTS5」经实测推翻：普通表上的 `LIKE '%kw%'` 用不到索引，而 trigram 索引可直接服务 `LIKE`，成本极低 |
| 7 | 默认快捷键 | **`Ctrl+Alt+V`（唤起）/ `Ctrl+Alt+C`（主动收藏），并改为首次启动由用户选定** | `Ctrl+Shift+V` 是 VS Code / Chrome / 终端的「粘贴为纯文本」，`Ctrl+Shift+C` 是终端「复制」，`RegisterHotKey` 全局独占会直接抢掉这些功能 |
| 7 | 命名与图标 | ClipNest，图标「鸟巢 + 剪贴」意象，后续设计 | 占位 |

> 其余未列细节（快捷键默认值、UI 布局）进入方案设计阶段细化。

## 8. 成功标准（MVP 验收）

- [ ] 复制任意文本后，托盘图标可感知到已捕获（可无打扰提示）
- [ ] 快捷键唤起窗口，3 秒内能搜到并重新复制一段 10 分钟前复制的内容
- [ ] 关闭应用再打开，历史数据完整保留
- [ ] 一键暂停后，复制内容不再被采集
- [ ] 全程无网络请求（可用防火墙验证）

## 9. 里程碑建议

| 阶段 | 目标 |
|------|------|
| M1 | 需求确认（本文档讨论定稿） |
| M2 | 方案设计（架构、数据模型、UI 选型） |
| M3 | MVP 开发（F1-F6 + S1-S2 + **F7 置顶 / F9 收藏**） |
| M4 | 内测打磨（F8 标签、F11 来源筛选、F12 类型图标、S5 导入导出） |
| M5 | 发布 v1.0 |

> **里程碑口径修正**：F7（置顶）与 F9（收藏）原本列为 P1，但容量策略是「超限时删除最旧的**非置顶、非收藏**条目」——
> 没有置顶/收藏，清理就无从区分优先级。因此这两项必须进 MVP，其余增强功能仍留在 M4。
